This area covers the tools that programmers use each day and how they fit into a workflow. It goes from the shell and the editor to version control, builds, packages and continuous integration.

## What it holds

- **The shell and the command line.** The shell as a daily tool: commands, pipes and redirection, the classic Unix text tools, terminals and remote shells.
- **Editors and IDEs.** Text editors and integrated development environments, the editing skills that pay off, and the protocols that join editors to language tools.
- **Version control.** What version control is, its models and history, and the main systems other than the Git details, which have their own sub-areas. The id changes so that the core slug version-control can be the concept page.
- **Git concepts.** How Git works: the object model, the index, refs, branches, merges, rebases, remotes and the files that configure a repository.
- **Git commands and tasks.** The Git commands in daily use, grouped by job, and the core tasks done with them. Commands without a page are sections of a group page.
- **Collaboration workflows.** How teams share changes: code hosts, pull requests, branching models, merge rules and the open source contribution flow.
- **Build systems.** Tools that turn source into programs: the ideas of build graphs and incremental builds, and the main build tools of each ecosystem.
- **Package managers and dependencies.** Tools that fetch, resolve and lock dependencies, and the system package managers that install tools.
- **Continuous integration and delivery.** Pipelines that build, test and ship each change, the practices behind them, and the main CI services.
- **Containers for developers.** Containers as a developer tool: images, Dockerfiles, local services with Compose and development containers. Container platforms are in distributed-and-cloud.
- **Documentation tools.** Tools that make documentation from code and plain text, and the formats they use. How to write good documentation is in construction-practice and software-engineering-process.
- **Code search and navigation.** Tools to search and navigate large code bases, from grep to semantic code intelligence.
- **HTTP and API tools.** Tools that programmers use to call and inspect HTTP and RPC services during development.
- **Local automation.** Tools that automate the routine steps of local work: hooks, task runners and watchers.
- **Toolchains and environment management.** Managing toolchain versions, environment variables, virtual environments and dotfiles so that a setup is repeatable.

## What it does not hold

- Kubernetes and container platforms for running services. They are in [Distributed and cloud programming](/distributed-and-cloud/).
- Supply-chain security of packages. It is in [Secure programming](/security/).
- The shell language as a language. It has a guide under [Languages](/languages/).
- Analyzers and linters. They are in [Program analysis and verification](/program-analysis-and-verification/).
