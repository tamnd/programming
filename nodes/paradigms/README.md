A paradigm is a style of programming with its own model of what a program is. This area describes each main style, the ideas that define it and the languages that support it. A language often supports more than one style.

## What it holds

- **What a paradigm is.** The idea of a programming paradigm, the ways to classify paradigms, and the measures that compare them. It opens the area.
- **Imperative programming.** Programs as sequences of commands that change state.
- **Structured programming.** Programs built from sequence, selection and iteration, with one entry and one exit, and designed from the top down.
- **Object-oriented programming.** Object-oriented programming as a paradigm: objects that hold state and behaviour, and the two main families of object systems. The mechanics (classes, inheritance, dispatch) go to objects-and-classes.
- **Functional programming.** Programs as the evaluation of expressions and the composition of functions, without changes to state.
- **Logic programming.** Programs as facts and rules of logic, run by a search for proofs.
- **Declarative programming.** Programs that state what result is wanted, not the steps to get it.
- **Dataflow and reactive programming.** Programs as graphs of values that flow and update when their inputs change.
- **Array-oriented programming.** Programs that work on whole arrays at once. NumPy and data frames go to data-science-and-ml-programming/array-programming.
- **Concatenative programming.** Programs built by putting functions side by side, where each function works on a shared stack.
- **Event-driven programming.** Programs whose flow is set by events: user input, messages, timers and signals.
- **Aspect-oriented programming.** Programs that put cross-cutting concerns, such as logging and security checks, into separate units called aspects.
- **Actor-oriented programming.** Programs as actors that own their state and talk only by messages. The runtimes and the libraries go to concurrency-and-parallelism/actor-systems.
- **Multi-paradigm programming.** Languages that mix paradigms, and how to choose a style for a problem. This sub-area is small by nature: scripting languages, DSLs and polyglot systems are kinds of language, so they go to languages and metaprogramming.
- **Other paradigms.** The smaller and newer paradigms that do not fit the families above. Each page is short and links to the area that holds the practice.

## What it does not hold

- The detail of each construct, such as closures or classes. Each has its own area, such as [Functions and abstraction](/functions-and-abstraction/) and [Objects and classes](/objects-and-classes/). A paradigm page links to them.
- Actor runtimes and libraries as tools for concurrent programs. They are in [Concurrency and parallelism](/concurrency-and-parallelism/).
- Array libraries for data work, such as NumPy as a tool. They are in [Data science and ML programming](/data-science-and-ml-programming/).
