This area covers programs that run in a browser or that answer HTTP requests. It goes from HTTP, HTML and CSS to the DOM, frameworks, APIs, authentication flows, performance and accessibility.

## What it holds

- HTTP for programmers: methods, status codes, headers and caching, as code sees them.
- HTML: elements, attributes, the document outline and semantic markup.
- CSS: the cascade, specificity, the box model, flexbox and grid.
- The DOM and Web APIs: the DOM and the Web APIs of the browser.
- Front-end frameworks: front-end frameworks, such as React and Vue.
- Back-end frameworks: back-end frameworks, such as Django and Express.
- REST, GraphQL and RPC: styles of web API, and how to choose between them.
- Authentication flows: login, OAuth and other authentication flows on the web.
- Web performance: the speed of web pages and how to measure it.
- Accessibility in code: accessible web pages, in code.
- Browsers as runtimes: the browser as a runtime, and WebAssembly on the web.

## What it does not hold

- JavaScript and TypeScript as languages. They have guides under [Languages](/languages/).
- Injection and cross-site scripting as weaknesses. They are in [Secure programming](/security/).
- Distributed systems behind a web service. They are in [Distributed and cloud programming](/distributed-and-cloud/).
- Web design as a visual subject. It is out of scope.
