This area covers programs that run in a browser or that answer HTTP requests. It goes from HTTP, HTML and CSS to the DOM, frameworks, APIs, authentication flows, performance and accessibility.

## What it holds

- **HTTP for programmers.** HTTP as a client and a server program sees it, and the URLs and media types that go with it.
- **Web servers.** How a program serves HTTP, and the servers and proxies in front of it.
- **HTML generation and markup formats.** How programs produce, parse and clean HTML, and the markup formats around it. The HTML language is in the HTML tree.
- **CSS in projects.** How teams organize, build and ship CSS. The CSS language is in the CSS tree.
- **The DOM and Web APIs.** The DOM and the browser APIs that scripts call. The language side is in the JavaScript tree.
- **Browsers as runtimes.** How a browser loads, runs and isolates web code, and the tools to inspect it.
- **Front-end frameworks.** Component frameworks for browser UIs, their models of state and rendering, and their meta-frameworks.
- **Web application architecture.** Where the HTML is built and when: server pages, single-page apps, static generation and hybrids.
- **Back-end web frameworks.** Server frameworks: routing, middleware, templates, request validation and the main frameworks of each ecosystem.
- **Web build tools.** Bundlers, transpilers and dev servers for front-end code. The core tools webpack and vite are pages in tools-and-workflow; this sub-area links them.
- **HTTP APIs.** Web API styles over HTTP: REST, GraphQL, gRPC and the others, and the tools to describe and test them. API design in general is in software-design.
- **Real-time web.** Push from server to client and two-way messages in the browser.
- **Authentication flows.** How web and API clients prove who they are: sessions, tokens, OAuth 2.0, OpenID Connect and passkeys. Cryptography and the weaknesses are in security.
- **Web performance.** How to measure and improve the speed of web pages and their servers.
- **Accessibility in code.** How code makes web and app interfaces usable with assistive technology, and how to test it. The markup semantics and ARIA attributes are in the HTML tree.

## What it does not hold

- JavaScript and TypeScript as languages. They have guides under [Languages](/languages/).
- Injection and cross-site scripting as weaknesses. They are in [Secure programming](/security/).
- Distributed systems behind a web service. They are in [Distributed and cloud programming](/distributed-and-cloud/).
- Web design as a visual subject. It is out of scope.
