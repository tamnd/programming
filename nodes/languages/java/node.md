## Overview

Java is a general-purpose, concurrent, class-based and object-oriented language. Its specification, the Java Language Specification (JLS), says that Java is related to C and C++ but is organized rather differently. The JLS calls Java "a production language, not a research language".[^1]

Java began in a research project for software on network devices and embedded systems. The project first used C++, but the problems with C++ grew until the team made a language of its own.[^2] The first prototype of the Java Virtual Machine (JVM) was made at Sun Microsystems. The HotJava browser first showed the language at work, with programs embedded in web pages.[^3]

A white paper of May 1996 by James Gosling and Henry McGilton puts the design goals under five headings. The language must be object oriented and familiar; reliable and secure; architecture neutral and portable; high in performance; and interpreted, threaded and dynamic. It has no pointer arithmetic, and a garbage collector reclaims memory automatically.[^2]

Each release of the Java SE Platform has its own edition of the JLS and of the JVM Specification. Java SE 27 came out in September 2026 as Java Specification Request (JSR) 402 of the Java Community Process.[^4][^5] The JLS names `javac` as the reference compiler.[^6] Oracle publishes the specifications under a limited licence grant. The grant allows internal evaluation and the distribution of compliant implementations, so it is not an open licence.[^7]

## A first program

```java run id=hello
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

```output for=hello
Hello, world!
```

The JVM starts a program by calling the `main` method of a class, and it passes the command-line arguments as an array of strings.[^8] From JDK 25, a compact source file can leave out the class, so `void main() { IO.println("Hello, world!"); }` is a whole program.[^9]

The program below models arithmetic expressions as a tree. A sealed interface lists the permitted kinds of node, and three records implement it.

```java run id=expr
import java.util.List;
import java.util.stream.Stream;

public class Main {
    sealed interface Expr permits Num, Add, Mul {}

    record Num(int value) implements Expr {}

    record Add(Expr left, Expr right) implements Expr {}

    record Mul(Expr left, Expr right) implements Expr {}

    static int eval(Expr expr) {
        return switch (expr) {
            case Num n -> n.value();
            case Add(Expr left, Expr right) -> eval(left) + eval(right);
            case Mul(Expr left, Expr right) -> eval(left) * eval(right);
        };
    }

    public static void main(String[] args) {
        Expr a = new Add(new Num(2), new Mul(new Num(3), new Num(4)));
        Expr b = new Mul(new Add(new Num(2), new Num(3)), new Num(4));
        List<Integer> values = Stream.of(a, b).map(Main::eval).toList();
        System.out.println(values);
        System.out.println(new Num(7).equals(new Num(7)));
    }
}
```

```output for=expr
[14, 20]
true
```

The `switch` in `eval` has no `default` case. The interface is sealed, so the compiler knows every subtype and checks that the cases cover them all.[^10][^11] A record pattern such as `Add(Expr left, Expr right)` matches a record and binds its components to variables.[^12] The compiler writes the accessors and the `equals` method of a record from its components, so the two `Num(7)` values are equal.[^13]

## The language at a glance

A source file has the extension `.java`. The JLS lets a host that stores packages in files require each public class to be in a file named after it. The extension can be `.java` or `.jav`, for example.[^14] GitHub Linguist counts files with the extensions `.java`, `.jav` and `.jsh` as Java.[^15]

**Types.** Java is statically typed: every variable and every expression has a type that is known at compile time. It is also strongly typed ([[static-and-dynamic-typing]]).[^16] The primitive types are `boolean`, `byte`, `short`, `int`, `long`, `char`, `float` and `double`. The reference types are classes, interfaces and arrays, and there is a special null type.[^16] The integer operators do not indicate overflow in any way ([[integer-overflow]]).[^17] From JDK 10, `var` declares a local variable whose type the compiler infers from the initializer.[^18][^19] Classes, interfaces and methods can declare type parameters ([[parametric-polymorphism]]). The compiler erases most of this type information, so a `List<String>` and a `List<Integer>` have the same class at run time ([[type-erasure]]).[^20]

```java run id=types
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        int big = Integer.MAX_VALUE;
        System.out.println(big + 1);
        Integer small = 127;
        Integer sameSmall = 127;
        Integer large = 1000;
        Integer sameLarge = 1000;
        System.out.println(small == sameSmall);
        System.out.println(large == sameLarge);
        System.out.println(large.equals(sameLarge));
        List<String> names = new ArrayList<>();
        List<Integer> numbers = new ArrayList<>();
        System.out.println(names.getClass() == numbers.getClass());
    }
}
```

```output for=types
-2147483648
true
false
true
true
```

The `==` operator on two references tests whether they refer to the same object, and the `equals` method compares values.[^21] The JLS requires boxing to give the same object only for small values, such as the integers from -128 to 127. For 1000, the result of `==` depends on the implementation.[^22]

**Memory.** A program creates objects and never frees them by hand. The JLS describes automatic storage management, typically with a garbage collector ([[garbage-collection]]).[^1] The HotSpot virtual machine of the JDK has several collectors. G1 is the default, ZGC aims at pause times under a millisecond, and the Serial and Parallel collectors are also available.[^23]

**Execution.** The compiler translates source code to a machine-independent bytecode format.[^1] The JVM knows only the class file format that holds the bytecode, not the Java language, and it is not inherently interpreted.[^3] At run time an implementation may generate machine code and optimize the program dynamically.[^1] On Android, the Android Runtime (ART) runs the Dalvik executable (DEX) format and its bytecode.[^24]

**Paradigms.** Code lives in classes and interfaces, which belong to packages.[^14] Lambda expressions and method references pass behaviour as values ([[higher-order-functions]]).[^25] The JEP for sealed classes says that records express product types and sealed classes express sum types, which together give algebraic data types ([[sum-types]]).[^10] Threads and locks are part of the language ([[threads]], [[mutual-exclusion]]).[^26]

## Versions and support

OpenJDK makes a feature release every six months. JEP 322 defines version numbers of the form `$FEATURE.$INTERIM.$UPDATE.$PATCH`. It says that the March 2018 release was JDK 10 and the September 2018 release JDK 11.[^27] Update releases come on the third Tuesday of January, April, July and October.[^28]

Oracle names Java SE 8, 11, 17, 21 and 25 as long-term support (LTS) releases. It plans Java 29 for September 2027 as the next. An LTS release gets Premier Support and then Extended Support. A release that is not LTS gets support until the next feature release.[^29][^30] Other vendors set their own dates. Eclipse Temurin, for example, supports 17 to 2027-10 and 21 to 2029-12.[^31]

## History and influence

Wikidata and PLDB give 1995 as the year Java appeared, and both name James Gosling as its designer.[^58][^59]

| Date | Event |
|---|---|
| May 1996 | JDK 1.0.2, the first row in the table of class file versions of the JVM Specification[^3] |
| 2006 | the start of the OpenJDK Community[^60] |
| 2014-03-18 | JDK 8, whose single driving feature was Project Lambda[^61] |
| March 2018 | JDK 10, the first release numbered under the six-month release model[^27] |
| 2023-09-19 | JDK 21, with virtual threads as a final feature[^62][^63] |
| 2026-09-15 | JDK 27, the reference implementation of Java SE 27[^33] |

Oracle appoints the OpenJDK Lead, who directs the JDK Release Projects and leads each one.[^60] A Governing Board oversees the health of the Community, but it has no direct authority over technical or release decisions.[^64] A change to the JDK starts as a JDK Enhancement Proposal (JEP). Decisions on proposals are ultimately up to the OpenJDK Lead. The Java Community Process (JCP) remains the governing body for the standard Java SE APIs.[^65]

The JLS says that the lexical structure of Java is based on C and C++. Its threads and locks are based on the monitors of Mesa.[^26] The white paper names Eiffel, Smalltalk, Objective-C and Cedar/Mesa as sources of design and architecture decisions.[^2]

## Coming from another language

- A method or constructor must handle each checked exception that it can cause, or name it in its `throws` clause. `RuntimeException`, `Error` and their subclasses are unchecked ([[exception-handling]]).[^66]
- Any reference can be `null`, and a call of an instance method on a null reference throws a `NullPointerException` ([[null-references]]).[^67] `Optional` is mainly for method return types that may have no result.[^68]
- Primitive values are not objects, and a type argument must be a reference type. So a `List` holds boxed `Integer` objects, not `int` values, and `==` on two boxes compares identity.[^16][^22]
- Type arguments are erased at compile time, so a program cannot ask at run time whether a list holds strings ([[type-erasure]]).[^20]
- From JDK 21, virtual threads are lightweight threads for high-throughput concurrent applications ([[threads]]).[^63]
