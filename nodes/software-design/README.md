This area is about the shape of a program above the level of a single function. It covers the principles that guide design, the catalogue of design patterns, architecture styles and the design of APIs.

## What it holds

- Design principles: SOLID, DRY, KISS, YAGNI, cohesion and coupling, and separation of concerns.
- Creational patterns: patterns that make objects, such as factory method and builder.
- Structural patterns: patterns that combine objects, such as adapter and composite.
- Behavioral patterns: patterns that share work between objects, such as strategy and observer.
- Architecture styles and patterns: architecture styles, such as layers, hexagonal architecture and event sourcing.
- Domain-driven design: bounded contexts, aggregates and the language of the domain.
- API design: how to design an interface that other programmers use.
- Modularity: splitting a system into modules with clear boundaries.
- Design for change: design that keeps the cost of a future change small.

## What it does not hold

- The language features that patterns use, such as interfaces and closures. They are in [Objects and classes](/objects-and-classes/) and [Functions and abstraction](/functions-and-abstraction/).
- Microservices and distributed architecture. They are in [Distributed and cloud programming](/distributed-and-cloud/).
- Code-level practice, such as naming and refactoring. It is in [Construction practice](/construction-practice/).
- HTTP API styles, such as REST and GraphQL. They are in [Web development](/web-development/).
